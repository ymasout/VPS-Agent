# M5.4：单 Agent / 单服务上下文只读会话

本文定义 M5.4 的第一垂直切片：在同一个实现中增加单 Agent 与单业务服务两种页面上下文会话。两个入口共用 M5.1/M5.2.2 的轮次、Provider、结构化回答、真实引用、历史、超时与失败处理，但拥有彼此独立且不可由自然语言改变的数据作用域。

当前状态：**实现提交 `58f3308` 已部署，生产金丝雀于 2026-07-26 通过；生产已还原 `CONVERSATION_CONTEXT_CHAT_ENABLED=false`。** 新迁移为 `0014_m5_context_scope`。

## 1. 目标

1. 在机器详情页提供当前 Agent 的只读上下文会话。
2. 对已建立诊断映射的业务服务提供独立服务会话页。
3. Agent 会话只读取当前组织、当前 Agent 的控制平面记录。
4. 服务会话只读取当前组织、当前 `ManagedService` 及其明确关联实例的控制平面记录。
5. 继续返回事实、推断、建议、缺失信息和服务端验证过的真实引用。
6. 两个入口共用确定性/HTTP JSON Provider、上下文预算、历史、严格 schema 和受控失败。
7. GET 在目标存在但没有会话时返回 `200 + session_id=null + turns=[]`；不存在或跨组织统一返回 404。

## 2. 非目标

- Fleet 全局对话、跨 Agent/跨服务搜索或自动选择多个目标。
- 从问题正文、Provider 输出或请求体读取 Agent ID、服务 ID、实例 ID或其他选择器。
- 新取日志、领取 Agent 证据任务、访问 VPS/Agent/Docker 或触发 GitHub 网络请求。
- 创建、确认、取消、领取或执行 Operation。
- 会话到部署计划交接、自动修复、自动回滚、Shell、任意命令或任意路径。
- 修改 M4 v1/v2 协议、签名、确认、状态机、验证窗口或 Agent 能力策略。

## 3. 一步实现两个作用域的原因

两个作用域共享相同的安全生命周期和 UI 行为，差异只在可信根目标与上下文查询：

| 项目 | Agent scope | Service scope |
| --- | --- | --- |
| `scope_type` | `agent` | `service` |
| 数据库可信目标 | `conversation_sessions.agent_id` | `conversation_sessions.service_id` |
| Web 入口 | `/servers/{agent_id}` | `/servers/{agent_id}/services/{instance_id}` |
| API 路由目标 | `agent_id` | `instance_id`，服务端派生 `service_id` |
| 允许的 Agent | 当前 Agent | 当前服务明确关联实例所在 Agent |
| 允许的服务实例 | 当前 Agent 上已映射实例 | 当前 `ManagedService` 的实例 |
| 允许的事件/诊断/证据 | 当前 Agent 链路 | 当前服务实例稳定身份链路 |
| 允许的 Operation 摘要 | `operation.agent_id` 匹配 | `operation.instance_id` 属于当前服务 |

一次实现不表示混合上下文。两种 session 具有不同外键、唯一约束、查询和落库前二次校验；历史也不会互通。

## 4. 威胁模型

| 威胁 | 控制 |
| --- | --- |
| 问题中要求读取其他 Agent/服务 | 问题仅作为不可信正文；所有选数来自 URL 与数据库外键 |
| 跨组织 IDOR | 根目标先按组织查询；session 使用 `(target_id, organization_id)` 复合外键；不匹配返回 404 |
| 一个 session 同时绑定多个 scope | 数据库 CHECK 要求 event/repository/agent/service 四种目标恰好一个 |
| 服务实例被用来伪造其他业务服务 | API 先按组织联结 `ServiceInstance -> ManagedService -> Agent`，再由服务端派生 `service_id` |
| 提示注入要求创建 Operation | Provider 无工具；上下文模块无操作创建入口；PG 门控比较 Operation/Transition 计数 |
| 引用在 Provider 调用期间越界或删除 | 落库前重新查询当前 scope 的允许 Agent、实例、事件、诊断、证据和 Operation ID 集合 |
| 原始日志或详情泄露敏感值 | 所有正文进入预算前再次脱敏并截断；不包含凭据、签名、nonce、计划或原始 transition details |
| 上下文洪泛 | 沿用 128 KiB 总预算、单项上限、数量上限及“事实项优先、历史使用剩余预算”规则 |
| 浏览器跨站提交 | 两个 POST 代理均执行同源校验；管理令牌只在 Web 服务端加入 |
| 功能误开放 | 独立开关默认关闭；GET 可展示历史但 POST 返回 `403 feature_disabled` |

## 5. 数据模型与迁移

`0014_m5_context_scope`：

- 为 `agents(id, organization_id)` 与 `managed_services(id, organization_id)` 增加可被复合引用的唯一约束。
- 为 `conversation_sessions` 增加可空 `agent_id`、`service_id`、索引和 `(organization_id, target_id)` 唯一约束。
- 增加组织复合外键：
  - `(agent_id, organization_id) -> agents(id, organization_id)`
  - `(service_id, organization_id) -> managed_services(id, organization_id)`
- 扩展 scope CHECK，要求 `event/repository/agent/service` 四种目标恰好一个。
- downgrade 在存在 Agent/服务会话时失败关闭，避免静默删除历史。

不增加新的消息表或引用类型。现有 `agent_summary`、`service_instance_summary`、`alert_event`、`diagnostic_run`、`evidence_item` 和 `operation` 已能表达首片只读证据。

## 6. API

### Agent

- `GET /api/v1/agents/{agent_id}/conversation`
- `POST /api/v1/agents/{agent_id}/conversation/turns`

### 服务

- `GET /api/v1/service-instances/{instance_id}/conversation`
- `POST /api/v1/service-instances/{instance_id}/conversation/turns`

GET 返回：

```json
{
  "scope_type": "agent",
  "target_id": "server-derived-id",
  "parent_agent_id": "server-derived-agent-id",
  "title": "display name",
  "session_id": null,
  "available": false,
  "unavailable_reason": "feature_disabled",
  "turns": []
}
```

POST 请求继续只接受：

```json
{
  "client_request_id": "UUID",
  "question": "最多 2000 字符且 UTF-8 不超过 8 KiB"
}
```

请求体不接受 scope、Agent、服务、实例、事件、诊断、证据、操作、路径、命令或确认字段。重复 `client_request_id` 返回原轮次；同 session 同时只能有一个活动轮次。

## 7. 上下文与引用

优先顺序：

1. 当前 Agent 摘要与最新指标。
2. 当前作用域内已映射服务实例及当前状态。
3. 最近相关事件。
4. 最近诊断和有限证据。
5. 当前作用域内 Operation 的只读有限摘要。
6. 使用剩余预算加入最多 10 轮历史。

所有业务正文均以不可信数据传给 Provider。首片不在 Agent/服务上下文中加入仓库正文；仓库会话继续走 M5.2.2，事件部署知识继续走 M5.2.1。

Provider 只能引用本轮服务端生成的 `ctx_*`。答案结构校验、未知引用拒绝、再次脱敏及引用关系落库沿用 M5.1。Agent/服务引用在落库前按当前组织和当前 scope 重新查询；`repository_file` 在这两个 scope 中一律不允许。

## 8. Web 最小交互

- 机器详情页显示一个 Agent 只读会话面板。
- 已映射服务卡显示“打开服务会话”，进入独立服务页。
- 面板展示历史、结构化回答、引用、加载/失败状态、字符和字节限制。
- 功能关闭时保留历史只读展示，输入框和发送按钮禁用。
- 页面明确说明不访问 VPS/Agent/GitHub 网络，不创建或确认 Operation。

## 9. 测试矩阵

- 默认开关关闭；关闭时 POST 为 403。
- 目标存在但无 session 返回 200 空历史。
- Agent/服务根查询显式包含组织过滤。
- 服务 ID 由 instance 路由服务端派生。
- 请求只新增 ConversationSession/Turn，不新增 Operation。
- 同源代理不向浏览器泄露管理令牌并拒绝跨站请求。
- UI 分别显示 Agent/服务语义和只读边界。
- 真实 PostgreSQL：
  - 跨组织 Agent/服务复合外键拒绝；
  - 混合 scope CHECK 拒绝；
  - 两种轮次均完成并保存对应 manifest；
  - 恶意证据被再次脱敏且不能产生写副作用；
  - 引用均属于当前组织和 scope；
  - M5.1/M5.2.1/M5.2.2/M5.3.1/M5.3.2/M5.3.3 门控不回归；
  - `0013 -> 0014 -> 0013 -> 0014` 与 schema check 通过。
